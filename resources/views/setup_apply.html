They're changed in the running server: no restart, no downtime. They're also written to {{$.Data.Cfg.MySQL.ConfFile}}, so they survive a restart and a restore.

With enforce_gtid_consistency on, MySQL refuses the few statements that GTIDs can't log safely: mostly writing to a MyISAM table and an InnoDB table in one transaction, and CREATE TABLE … SELECT into a MyISAM table. Apps that only use InnoDB aren't affected.{{if .Task.NonInnoDB}} This server has {{.Task.NonInnoDB}} table(s) that aren't InnoDB: check how your app writes to them first.{{end}}

Changing these settings needs MySQL's root, once. The password is never stored.

Or make the change later from the command line: sudo liops setup --enable-gtid, then come back.
